# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Build System

This project uses **XcodeGen** to generate the Xcode project from `project.yml`.

```bash
# Regenerate Xcode project after changing project.yml
xcodegen generate

# Build iOS target
xcodebuild -project Odin.xcodeproj -scheme Odin_iOS -destination 'platform=iOS Simulator,name=iPhone 17' build

# Build macOS target
xcodebuild -project Odin.xcodeproj -scheme Odin_macOS build
```

There are no tests, linter, or formatter configured.

## Architecture

**Odin** is a personal productivity app (Todos, Notes, Remote/SSH; plus Claude sessions on macOS) for iPhone and Mac, built as a single multiplatform SwiftUI project targeting iOS 18+ and macOS 15+.

### Data & Sync
- **SwiftData** with `@Model` macro for persistence. All model properties must have defaults (CloudKit requirement).
- **CloudKit** syncs data automatically via iCloud — no custom networking or auth needed.
- `ModelContainer` is set up in `OdinApp.swift` and injected via SwiftUI environment.
- **CloudKit environment is pinned to Production** via `com.apple.developer.icloud-container-environment = Production` in `Odin/Odin.entitlements`. Without this, Debug builds (Xcode → iPhone) silently target the Development CloudKit DB while Release / Developer-ID Mac builds target Production, and data created on one is invisible on the other (same container ID, separate record stores). Cost of pinning: Production schema does NOT auto-evolve, so every time a new `@Model` or property is added you must deploy schema dev → prod in [CloudKit Console](https://icloud.developer.apple.com/) before any build can write the new field, otherwise writes fail.

### Navigation
`ContentView.swift` uses a `TabView` with `AppTab` enum. macOS: `claude` (default), `remote`, `notes`, `todos`. iOS: `remote`, `notes`, `todos`, `settings` (default `.todos`). A `@State` binding controls the selected tab. The Remote terminal view receives a `$selectedTab` binding to navigate back to Todos programmatically (since the tab bar is hidden when connected; the iOS terminal also has its own Disconnect button so users can drop the SSH session without force-quitting). macOS uses a custom `MacTabBar` with inline `⌃1…⌃4` hints and an "About Odin" button in the trailing corner; iOS reaches `SettingsView` via the dedicated tab.

### Feature Modules
Each feature lives in `Odin/Features/<Name>/` with its own views and services. Models live in `Odin/Models/`. Todos and Notes are complete. Remote/SSH (the GCP VM terminal) is complete including the iOS accessory bar, pinch-zoom font control, and auto-reconnect backoff. Claude Terminal (macOS-only) launches Claude Code CLI in a local terminal. OdinMCP (macOS-only) gives those Claude sessions an in-process MCP server for dispatching scoped review/fix workers.

### Key Patterns
- `@Query` for reactive SwiftData fetching in list views
- `@Bindable` for mutating model properties in child views
- Sheet presentation for create/edit flows
- `NotificationManager` singleton wraps `UNUserNotificationCenter` for reminder scheduling

### Terminal Feature
Uses SwiftTerm (terminal emulation) + Citadel (SSH) to connect to a GCP VM. Key components:

- **TerminalContainerView** — orchestrates connection flow, overlay buttons (keyboard dismiss, navigate to Todos), mounts the iOS accessory bar via `.safeAreaInset` when the keyboard is up, applies `FontZoomShortcuts` on macOS
- **TerminalRepresentable** — `UIViewRepresentable`/`NSViewRepresentable` wrapping SwiftTerm's `TerminalView`; the iOS variant adds a pinch recognizer that writes the new size through `@AppStorage(TerminalFontSettings.key)`
- **TerminalAccessoryBar** (iOS) — SwiftUI bar with Esc/Tab/Ctrl/arrows/^C/^D/^Z/^L/^R; Ctrl is a sticky toggle. Implemented in SwiftUI because SwiftTerm's `TerminalView.inputAccessoryView` isn't open.
- **TerminalFontSettings** / **FontZoomShortcuts** — persisted font size shared by both terminals. Cmd+= / Cmd+- / Cmd+0 on macOS; pinch on iOS; slider in Settings.
- **TerminalViewModel** — `@Observable` state machine (idle → checkingKey → setupRequired → startingVM → connecting → connected → disconnected → reconnecting → error). Auto-reconnect with [2, 5, 10, 20, 30]s backoff on unexpected drops; user-initiated `cancelConnect`/`disconnect` suppresses it.
- **VMStarterService** — calls Cloud Function to start VM and get IP + SSH host key. Authenticates via `X-API-Key` header. Refuses to connect if host key is missing. Maps the function's HTTP 429 (rate-limit) response to `VMStarterError.rateLimited(retryAfter:)`.
- **SSHService** — Citadel SSH client with Ed25519 auth and mandatory host key verification via `.trustedKeys()`. The full OpenSSH key string (e.g. `ssh-ed25519 AAAA...`) is passed from the Cloud Function response.
- **SSHKeyManager** — Ed25519 key generation and Keychain storage (`kSecAttrAccessibleWhenUnlockedThisDeviceOnly`). Optional biometric protection via `SecAccessControlCreateWithFlags(.biometryCurrentSet)`; `setBiometricProtection(_:)` re-stores the existing key without regenerating so the GCP-side public key stays valid. Toggled from Settings.
- **APIKeyManager** — Stores the Cloud Function API key in Keychain. No secrets in source code. The setup screen prompts for the key on first use.
- **OdinTerminalView** — iOS subclass of `TerminalView` adding mouse wheel events (SGR escape sequences for tmux scroll), tap-to-focus gesture, pinch-to-zoom that updates `TerminalFontSettings`, and UIScrollView pan blocking when mouse mode is active

### Claude Terminal Feature (macOS only)
Uses SwiftTerm's `LocalProcess` to spawn the Claude Code CLI in a local PTY — no SSH or Cloud Function needed. Lives in `Odin/Features/Claude/`. Guarded by `#if os(macOS)` so iOS compilation is unaffected.

Multi-session: the Claude tab is a split view with a sidebar listing all sessions and a detail pane showing the selected session's terminal. Sessions persist as directory paths in `UserDefaults` (key `claude.sessionDirectories`) and are restored in `.notStarted` state on launch — clicking a row starts Claude in that directory.

Adding a session prompts twice: an `NSOpenPanel` picks a folder, then an `NSAlert` collects a worktree name and offers a "Use this folder directly (no worktree)" checkbox (bridged to the name field via `WorktreePromptCoordinator`, which greys the field out when checked). Two outcomes:
- **Worktree mode (default)** — `WorktreeService.create(sourcePath:name:)` validates the name with an allow-list regex (`^[A-Za-z0-9][A-Za-z0-9._/-]{0,127}$` plus an explicit `..` check — robustness, not injection defence, since git args go via `Process` arguments not a shell), runs `git rev-parse --git-dir` (must succeed), then `git fetch origin`, resolves origin's default branch via `git symbolic-ref --short refs/remotes/origin/HEAD` (falling back to parsing `git remote show origin` for `HEAD branch:` if the symbolic ref is unset), then `git worktree add -b <name> -- <parent>/<base>--<name> <origin/default>` where `<base>` is the source folder's name stripped of any existing `--suffix` (so worktrees of worktrees stay flat). The session opens in the new worktree path. New branches start from up-to-date `origin/<default>` rather than the source folder's current HEAD.
- **Direct mode (checkbox checked)** — skips `WorktreeService.create` entirely; the selected folder path goes straight into `store.addSession(directory:)`. Works on non-git folders too — Claude just runs in whatever directory was picked.

- **ClaudeSession** — `@Observable` model for one session: `id`, `workingDirectory`, `displayName` (folder's last path component), and an owned `LocalTerminalViewModel`. The view model survives detail-view rebuilds so the process keeps running across session switches (though scrollback resets, since SwiftUI creates a new `TerminalView` per `.id(session.id)` mount).
- **ClaudeSessionStore** — `@Observable` store injected via `@Environment` from `OdinApp`. Holds the session list and `selectedSessionID`. `addSession(directory:)` creates and persists; `select(_:)` sets selection and auto-starts Claude if `.notStarted`; `remove(_:)` calls `LocalProcess.terminate()`, drops the session, and persists.
- **ClaudeSessionListView** — Claude tab content. `HSplitView` with sidebar (header + `+` button + `List` of `ClaudeSessionRow`) and detail (`ClaudeSessionDetailView`). Hidden buttons in the view's `.background` register ⌘1…⌘9 to jump to the first nine sessions.
- **ClaudeSessionRow** — left side: an 8pt session-status dot, evaluated top-down (first match wins): `!running` → grey, `awaitingPermission` → green, `awaitingInput` → green, `isCompacting` → orange pulsing, `isActive` → yellow pulsing, `isSelected` → grey, `didFinish` → yellow stable, default → grey. (Permission and input were originally distinguished cyan vs green; commit `4a8cd32` unified them into a single green "needs attention" dot — the underlying flags still exist and `awaitingPermission` still outranks `awaitingInput`, but the colour is the same.) Selection only forces grey when the session is idle, not when Claude needs the user. The flags come from three sources: Claude Code's `PermissionRequest` hook, its `Notification` hook, or the PTY-output heartbeat in `LocalTerminalViewModel` (catches menus/prompts that don't fire `Notification`). They clear only when Claude resumes streaming output (`noteDataReceived`) or transitions through `working`/`idle` (`applyHookState`) — clicking the row does NOT acknowledge them, because looking isn't the same as responding. `didFinish` (yellow stable) IS cleared on click and on being-watched, via `acknowledge()`. Right of the folder name (in order): an optional `person.2.fill` + count badge when the session has running subagents (driven by `SubagentStart`/`SubagentStop` hooks → `activeSubagents` counter); then a green `checkmark.circle.fill` when `pendingNotifications` is non-empty (an OdinMCP background task completed); or 🤔 when an OdinMCP runner is in flight. "⌘N" hint on the far right for the first nine rows. Right-click → Remove.
- **ClaudeSessionDetailView** — wraps `TerminalRepresentable` with state overlays (`.starting` spinner, `.exited` / `.error` retry overlays). Calls `makeFirstResponder` on the terminal in `.onAppear` and when state becomes `.running`, so selecting a row puts focus in the terminal immediately.
- **LocalTerminalViewModel** — `@Observable` state machine (notStarted → starting → running → exited → error). Resolves the `claude` binary path via `ClaudePath.resolve()` against a fixed allow-list of known install dirs (`~/.claude/local`, `/opt/homebrew/bin`, `/usr/local/bin`, `~/.local/bin`). The legacy `which claude` shell fallback was removed — sourcing rc files would let a poisoned `~/.zshrc` redirect every session to an attacker binary. Spawn is direct (no `zsh -ilc` wrapper) with an explicitly-set `PATH` covering those four dirs plus `/usr/bin:/bin`. Each start mints a per-launch `sessionId` ("s-<8 hex>"), sets `ODIN_SESSION_ID` in the child env, and writes a per-launch `.mcp.json` to `$TMPDIR` carrying `X-Session-Id` and `X-Odin-Auth` (the MCP shared secret — see OdinMCPServer). The view model registers itself with `OdinSessionRegistry` so background runners can find it to push notifications. Spawns with `TERM=xterm-256color` and `COLORTERM=truecolor`. Handles terminal resize via `TIOCSWINSZ` ioctl on the PTY — sizes go through `UInt16(clamping:)` because the embedded HSplitView can hand the terminal transient zero/negative dimensions during layout. Drives sidebar status (`isActive`, `awaitingInput`, `awaitingPermission`, `isCompacting`, `activeSubagents`, `didFinish`) from two sources: (a) a per-session state file at `~/.claude/odin-status/<sessionId>.state` that the `odin-status.sh` Claude Code hook writes (`working` on `UserPromptSubmit`/`PreToolUse`/`PostToolUse`/`PostCompact`, `idle` on `Stop`, `awaiting-input` on `Notification`, `awaiting-permission` on `PermissionRequest`, `compacting` on `PreCompact`, deleted on `SessionEnd`); the view model pre-creates the file and attaches a `DispatchSourceFileSystemObject` watcher with event mask `[.write, .extend, .delete, .rename, .attrib]`. The `.attrib` bit is there because subagent-start/stop nudge the file via `touch` (no content change). If the watcher ever fires `.delete` or `.rename` (atomic-replace hook write), `reattachStatusWatcherIfNeeded()` cancels the dead source and re-opens against the path on the next runloop tick; bails after `statusMaxReattachAttempts = 6` consecutive re-attaches to avoid runaway loops. (b) A 500ms PTY-output heartbeat (`DispatchSource` timer + `lastDataReceivedAt` timestamp). While `isActive` is true but `lastDataReceivedAt` is older than `heartbeatIdleThreshold` (6s), the heartbeat promotes the session to `awaitingInput`. `lastDataReceivedAt` is refreshed by two paths: real PTY output via `noteDataReceived` (from `ProcessBridge.onData`), and hook-driven `working`/`compacting` writes in `applyHookState` — so `PreToolUse`/`PostToolUse` pings keep the heartbeat alive across long Bash / MCP calls that produce no PTY output. `activeSubagents` is recounted on every watcher tick by listing entries in `~/.claude/odin-status/<sessionId>.subagents/`. Also exposes `pendingNotifications: [BackgroundNotification]` for the OdinMCP background-task checkmark. `terminate()` forwards to `LocalProcess.terminate()` (SIGTERM + FD cleanup) and deregisters from the session registry.
- **ProcessBridge** — `@MainActor` adapter conforming to `LocalProcessDelegate`. Bridges process callbacks (data received, terminated, window size) to the view model via closures. All callbacks dispatched on the main queue.

### OdinMCP — Background Claude Workers (macOS only)
Lives in `Odin/Features/OdinMCP/`. Boots from `OdinApp.init` (macOS-only `Task { @MainActor in ... }` block) which installs skills + hooks and starts the MCP server. Each Odin Claude tab launches with `--mcp-config` pointing at the server, so its Claude session can spawn headless `claude -p` workers and route completion notifications back to its UI.

- **OdinMCPServer** — `@MainActor` singleton. `NWListener` on `127.0.0.1` with an ephemeral port (`requiredLocalEndpoint` + an application-layer endpoint check enforce loopback-only). On `start()` mints a 32-byte hex `authToken` — every request must carry it via `X-Odin-Auth` or the server returns 401 (constant-time compare). Loopback alone isn't a trust boundary on macOS: any user-level process can hit 127.0.0.1, so the per-launch token is what actually gates access. Token is written into the per-session `.mcp.json` so Claude Code carries it automatically. `stop()` cancels the listener and clears the token (called on `NSApplication.willTerminateNotification`). Speaks MCP JSON-RPC 2.0 over HTTP at `POST /mcp`. Handles `initialize`, `notifications/initialized`, `tools/list`, `tools/call`, `ping`. Extracts `X-Session-Id` / `X-Review-Id` / `X-Concern` / `X-Task-Id` from request headers and stores each in a `CurrentMCPRequest` `@TaskLocal` for the duration of each request.
- **HTTPRequestParser** — minimal HTTP/1.1 head + Content-Length parser, one-shot per connection. Marked `@unchecked Sendable` because all access happens on the `.main` queue.
- **OdinMCPTools** — review-oriented tool surface: `start_review_run`, `run_background_task` (dispatches a Phase-1 reviewer — `review_id` and `concern` are required; the free-form generic spawn was removed when workers stopped running with bypass permissions), `submit_finding`, `complete_review_worker`, `submit_fix_result`, `get_review_run`, `get_task_status`, `await_task`, `stop_task`, `stop_review_run`. The orchestrator calls the first few; spawned workers call `submit_finding` / `submit_fix_result` via their scoped allow-list (see BackgroundClaudeRunner).
- **BackgroundTaskRegistry** — `@MainActor` singleton keyed by `t-<8 hex>`. Soft cap of 200 retained runners: running tasks are never evicted; the oldest completed/failed entries fall off when the registry grows past the cap. When every retained entry is still running (so nothing is evictable), `pruneIfNeeded` logs and bails rather than silently growing.
- **BackgroundClaudeRunner** — wraps `Foundation.Process` to spawn `claude -p "<prompt>" --allowed-tools <list>` (with `--model <id>` appended when the tool call supplied one). No `--dangerously-skip-permissions`. The allow-list is keyed off the worker's role (`ReviewWorkerContext.role`): reviewer = `Read,Grep,Glob,Bash,mcp__odin__submit_finding,mcp__odin__complete_review_worker`; fixer = `Read,Grep,Glob,Edit,Write,Bash,mcp__odin__submit_fix_result`; nil-context Swift fallback = `Read,Grep,Glob,Edit,Write,Bash`. Anything outside the list fails closed in headless `-p`. Pipes are streamed via `readabilityHandler` into a lock-protected `PipeBuffers` helper (256 KB cap, then `[output truncated]`) so a chatty worker can't deadlock by filling the 64 KB pipe buffer before the termination handler fires. On exit: (a) writes a notification to `~/.claude/odin-pending/<parent_session_id>.txt` for the hook to drain on next user prompt — worker stdout and prompt snippets are first passed through `sanitizeForWrapper` to neutralise any `<odin-background-notification>` / `</odin-background-notification>` an output could contain (closes the prompt-injection feedback loop), then capped at 8 KB; (b) pushes a `BackgroundNotification` into the parent tab's `LocalTerminalViewModel.pendingNotifications`.
- **OdinSessionRegistry** — weakly maps per-launch `sessionId → LocalTerminalViewModel`. Read by `BackgroundClaudeRunner.pushBannerToParent` to find which Claude tab to notify.
- **OdinSkillInstaller** — on app launch, writes `~/.claude/skills/odin-review/SKILL.md`. Always overwrites. Also removes `~/.claude/skills/odin-spawn/` and `~/.claude/skills/odin-orchestrate/` via a `retiredSkills` cleanup pass — those skills were built around free-form `run_background_task` and stopped matching the tool contract when reviewer-only routing landed. `odin-review` is the two-phase branch-review skill (Phase-1 read-only reviewers per concern, Phase-2 fix workers spawned by the review pane), pinning workers to Sonnet 4.6 via the `model` arg.
- **OdinHookInstaller** — writes two hook scripts (chmod 755) and merges matching entries into `~/.claude/settings.json` idempotently (skips if the exact `command` string already appears under that event). Both scripts key off `$ODIN_SESSION_ID` in the parent claude env. (1) `~/.claude/hooks/odin-pending.sh` — registered for `UserPromptSubmit`; drains `~/.claude/odin-pending/<sessionId>.txt` to stdout so completed-background-task summaries get injected into Claude's next turn. (2) `~/.claude/hooks/odin-status.sh <state>` — registered for many Claude Code lifecycle events: `UserPromptSubmit`/`PreToolUse`/`PostToolUse`/`PostCompact` → `working` (the last three are keepalive pings that refresh the PTY-silence heartbeat across long tool calls and post-compact resumption), `Stop` → `idle`, `Notification` → `awaiting-input`, `PermissionRequest` → `awaiting-permission`, `PreCompact` → `compacting`, `SubagentStart`/`SubagentStop` → `subagent-start`/`subagent-stop` (add/remove a marker file in `~/.claude/odin-status/<sessionId>.subagents/`, then `touch` the state file to nudge the watcher), `SessionEnd` → `delete`. `LocalTerminalViewModel`'s file watcher picks up every write and updates the sidebar dot.

#### Identity flow
`LocalTerminalViewModel.startClaude()` mints `sessionId = "s-<8 hex>"` and uses it in three places: the spawned claude's env (`ODIN_SESSION_ID=...`), the `.mcp.json` it writes (`headers: { X-Session-Id: ... }`), and `OdinSessionRegistry.register(self, for: sessionId)`. Every tool call from that tab carries the id; the server stuffs it into a TaskLocal; the runner stores it on creation; on completion the runner uses it to route both the pending file (consumed by the hook → Claude's context) and the UI banner (consumed by the sidebar → the human's eyes).

#### User-facing notification surface
- **Sidebar checkmark** (`ClaudeSessionRow`): green `checkmark.circle.fill` when `pendingNotifications` is non-empty; otherwise the existing active-state green dot.
- **Auto-dismiss on click**: `ClaudeSessionStore.select(_:)` snapshots the pending notifications visible at click time and dismisses only those, so a worker that completes between the click and a future MainActor tick gets its own row + checkmark instead of being silently cleared.
- **Context injection on next user prompt**: the `UserPromptSubmit` hook drains the pending file and prints its contents to stdout, which Claude Code prepends to Claude's next turn — so Claude sees the result even after the sidebar signal has been cleared by the user opening the tab.

#### Files written outside the repo (macOS only, on app launch)
- `~/.claude/skills/odin-review/SKILL.md` — always overwritten.
- `~/.claude/skills/odin-spawn/`, `~/.claude/skills/odin-orchestrate/` — *deleted* if present (retired skills).
- `~/.claude/hooks/odin-pending.sh`, `~/.claude/hooks/odin-status.sh` — always overwritten, chmod 755.
- `~/.claude/settings.json` — hook entries merged idempotently under `hooks.UserPromptSubmit`, `hooks.PreToolUse`, `hooks.PostToolUse`, `hooks.Stop`, `hooks.Notification`, `hooks.PermissionRequest`, `hooks.PreCompact`, `hooks.PostCompact`, `hooks.SubagentStart`, `hooks.SubagentStop`, `hooks.SessionEnd` (atomic write).
- `~/.claude/odin-pending/<sessionId>.txt` — per-session pending notifications (drained by the hook). Removed by `LocalTerminalViewModel.tearDownCurrentSession()` on session restart/terminate; stale files only survive if a worker writes one after teardown (harmless).
- `~/.claude/odin-status/<sessionId>.state` — per-session Claude lifecycle state written by `odin-status.sh` (`working`/`idle`/`awaiting-input`/`awaiting-permission`/`compacting`); pre-created by `LocalTerminalViewModel.startStatusWatcher` so a kqueue file source can observe in-place overwrites. Deleted on `SessionEnd` and on `tearDownCurrentSession()`.
- `~/.claude/odin-status/<sessionId>.subagents/` — directory of marker files, one per running Task-tool subagent. `SubagentStart` adds a uniquely-named file, `SubagentStop` removes one. Hook then `touch`es the `.state` file so the watcher fires; the app recounts directory entries to update `activeSubagents`. Removed entirely on `SessionEnd` / `tearDownCurrentSession()`.
- `$TMPDIR/odin-mcp-<random>.json` — per-launch MCP config. Removed by `LocalTerminalViewModel.tearDownCurrentSession()` on session restart/terminate.

### Claude Diff Side Panel (macOS only)
Lives in `Odin/Features/Claude/Diff/`. Renders an uncommitted-changes view (git status + per-file unified diff) inside each Claude session's detail view. Toggleable with ⇧⌘D; visibility persists in `@AppStorage("claude.diffPaneVisible")`. Each `ClaudeSession` owns one `DiffViewModel` so file list + selection survive detail-view rebuilds (same pattern as the terminal view model).

- **DiffPaneView** — `HSplitView`-friendly column with a header, file list (`ChangedFileRow`), and a `UnifiedDiffView` body. Calls `viewModel.activate()` / `deactivate()` in `.onAppear` / `.onDisappear` so the FSEvents watcher only runs while visible.
- **DiffViewModel** — `@Observable` per-session state. Holds `files`, `selectedFileID`, `selectedDiff` (parsed hunks), `selectedIsBinary`, `selectedTruncated`. Two monotonic counters (`refreshGeneration`, `loadGeneration`) discard stale async results when the watcher fires faster than git completes or the user re-selects mid-load. Capped at `renderLineCap = 2_000` lines per file to keep `LazyVStack` happy on huge diffs (`*.pbxproj` etc.).
- **DiffService** — read-only async wrappers around `git status --porcelain=v1 -z --untracked-files=all`, `git diff --numstat -M HEAD`, and `git diff --no-color -M HEAD -- <path>` (untracked files use `--no-index /dev/null <path>` to render the whole file as additions). Runs each process on `DispatchQueue.global(qos: .userInitiated)` via `withCheckedContinuation` so the UI thread never blocks on git. Untracked-file +/- counts come from a lightweight in-process line counter that also flags binaries on a NUL byte in the first 8 KB.
- **UnifiedDiffParser** — splits raw `git diff` output into `DiffHunk`s, parses `@@ -a,b +c,d @@` headers for line-number tracking, drops file-header preamble (`diff --git`, `index`, `+++`, `---`).
- **UnifiedDiffView** — renders hunks with GitHub-style two-column line gutters, +/− markers, green/red row tints, and a sticky-ish hunk header. Per-line text goes through `SyntaxHighlighter.shared.highlight(...)`. Shows a truncation footer when `isTruncated`.
- **SyntaxHighlighter** — `@MainActor` singleton wrapping Highlightr in `fastRender: true` mode (no WKWebView). Caches highlighted lines keyed by `language|theme|content` (cap 4 000); on overflow the cache is dropped wholesale (cheap, since hits dominate). Strips Highlightr's background attribute so the add/remove row tint shows through, keeps foreground colors. Theme switches between `atom-one-dark` / `atom-one-light` based on the current `colorScheme`.
- **WorktreeWatcher** — recursive FSEvents stream rooted at the worktree path, latency 0 + own debounce (300 ms), file-level events, skips paths matching `/.git/` or ending in `/.git` so git's own writes don't trigger a refresh storm. Lifecycle managed by `DiffViewModel.activate()` / `.deactivate()`.

Dependency: adds `Highlightr` (`raspu/Highlightr`, from 2.2.0) to `project.yml`, gated to `platforms: [macOS]`.

### Claude Shell Pane (macOS only)
Lives in `Odin/Features/Claude/ShellTerminalViewModel.swift`. Adds a second terminal below each Claude session — a plain login `zsh` rooted at the session's working directory, useful for running git commands or scripts alongside Claude. Toggleable with ⇧⌘T; per-session visibility (`ClaudeSession.shellPaneVisible`, in-memory only, not persisted across launches — matches the per-session pattern of `projectPanelVisible` / `rightPaneMode`). The detail view stacks the existing top area (terminal + optional diff pane) and the shell pane in a `VSplitView`. Each `ClaudeSession` owns one `ShellTerminalViewModel` so the zsh process and scrollback survive detail-view rebuilds (same pattern as `viewModel` and `diffViewModel`). The shell pane uses the Terminal.app "Homebrew" profile look (phosphor-green text + caret on a slightly-lifted dark grey background) via `useHomebrewTheme: true` + `backgroundColorOverride: TerminalTheme.shellBackground` on `TerminalRepresentable`, so it reads as a distinct sub-pane under the (pure black) Claude session terminal above.

- **ShellTerminalViewModel** — `@Observable` `@MainActor` state machine (notStarted → running → exited → error). Spawns `/bin/zsh -l` via SwiftTerm's `LocalProcess`, inherits the parent env plus `TERM=xterm-256color`, `COLORTERM=truecolor`, and a fallback `LANG=en_US.UTF-8`. `startIfNeeded()` is idempotent (`guard state == .notStarted`) so the `.onAppear` in `shellPane` is safe to fire repeatedly. `restart()` and `terminate()` bump a monotonic `currentLaunchToken` before tearing down the old `LocalProcess`; the bridge's `onTerminated` closure captures the launch token at start time and bails if it no longer matches, so a late SIGTERM callback from the old process can't clobber the new process's `.running` state.
- **ShellProcessBridge** — minimal `LocalProcessDelegate` adapter, same `nonisolated` + `MainActor.assumeIsolated` shape as `ProcessBridge` in `LocalTerminalViewModel`. No heartbeat, no status hook, no MCP wiring — this is just a dumb shell.
- `ClaudeSessionStore.remove(_:)` now terminates `shellViewModel` in addition to `viewModel`.

### Claude Project Panel (macOS only)
Lives in `Odin/Features/Claude/Project/`. Adds a per-session file-tree side panel rooted at the session's working directory, plus a paired read-only file viewer for inspecting code without leaving the app. Toggleable with ⇧⌘P; per-session visibility (`ClaudeSession.projectPanelVisible`, in-memory only, not persisted across launches). Each `ClaudeSession` owns one `ProjectPanelViewModel` so the loaded tree, expanded set, focused-node cursor, and currently-open file survive detail-view rebuilds. Sits in `ClaudeSessionDetailView`'s `HSplitView` between the session sidebar and the terminal, with the file viewer as a second column that only appears when a file is selected. Layout becomes `[sessions] | [project] | [file] | terminal (+ shell) | [diff | review]`.

- **ProjectFileNode** — value-type tree node (`url`, `name`, `isDirectory`, `children: [ProjectFileNode]?`). `nil` children means leaf (file); non-nil (possibly empty) means folder, matching SwiftUI's `List(_:children:)` convention.
- **ProjectService** — async loader on a background queue. For git repos, runs `git ls-files --others --cached --exclude-standard -z` once and builds the in-memory tree from one call (so `.gitignore` is honoured). For non-git folders, walks `FileManager.contentsOfDirectory` with `.skipsHiddenFiles`, skipping `.git/` and symlinks. Caps total nodes at 20 000 with a `truncated` flag. `loadFileContent(url:)` reads up to 1 MB, NUL-byte binary detection on the first 8 KB, UTF-8 with ISO-Latin-1 fallback. Mirrors `SyntaxHighlighter.language(forPath:)` internally because the highlighter is `@MainActor`-isolated and the service runs from a background queue.
- **ProjectPanelViewModel** — `@Observable` `@MainActor`. Holds `rootNode`, `expandedURLs: Set<URL>` (in-memory persistence of which folders are open), `selectedFileURL` + loaded contents (`selectedFileContent`, `selectedFileIsBinary`, `selectedFileTruncated`, `selectedFileLanguage`, `selectedFileIsLoading`), and three coordination primitives for keyboard focus: `focusedNodeURL` (tree cursor, independent of selection), `focusTarget: .tree | .viewer`, and `focusGeneration` (monotonic bump). Generation counters (`loadGeneration`, `fileLoadGeneration`) discard stale async loads — same pattern as `DiffViewModel`. `reload()` is idempotent and re-seeds the cursor on the first visible node when the tree comes in. `clearSelection()` closes the file viewer (used by Esc in `FileViewerView` and by the deep-link path when the target file fails to load). `pendingFocusLine: Int?` carries a 0-indexed line for deep links from other panels (most notably the review pane's clickable line numbers) — `openFile(at:line:)` sets both `selectedFileURL` and `pendingFocusLine`, then `FileViewerView` consumes it on content-load and clears it back to nil.
- **ProjectPanelView** — hand-rolled recursive `ProjectTreeRowView` instead of `List(_:children:)` so a folder-row click toggles expansion instead of selecting (SwiftUI's standard list semantics treat all clicks as selection). Single `.onKeyPress(keys:)` matches on `.upArrow` / `.downArrow` (move cursor through `viewModel.visibleNodes`), `.leftArrow` (collapse expanded folder, otherwise jump to parent), `.rightArrow` (expand collapsed folder, otherwise jump to first child), `.return` (toggle folder or open file + hand keyboard focus to the file viewer via `viewModel.requestFocus(.viewer)`). `ProjectRowLabel` paints separate tints for keyboard focus (`focusedNodeURL`) vs selection (`selectedFileURL`); both together get the strongest tint so the cursor is visible on the currently-open file. Click also moves the keyboard cursor + re-asserts tree focus, so mouse and keyboard interleave cleanly. Re-asserts `@FocusState` whenever `viewModel.focusGeneration` bumps and `focusTarget == .tree`.
- **FileViewerView** — read-only viewer with line numbers + Highlightr syntax highlighting (reuses the shared `SyntaxHighlighter.shared.highlight(line:language:isDark:)` from the diff pane). Markdown files get a preview toggle (eye icon, `⇧⌘M`) in the header that swaps to a `MarkdownUI` rendering; `showPreview` is local `@State`, so opening another `.md` keeps the mode while a non-markdown file just hides the toggle. Vertical-only `ScrollView` so each row's `.frame(maxWidth: .infinity)` actually expands to the column width and wrapped lines reflow when the splitter is dragged. Per-line gutter width is computed from `String(lines.count).count * 7 + 6`. Owns its own `@FocusState contentFocused` + `@State focusedLine` (0-indexed, resets to 0 on every new file). Single `.onKeyPress(keys:)` for `.upArrow` / `.downArrow` to move `focusedLine` with `ScrollViewReader` proxy auto-scrolling to `.center`. Esc closes the file via `viewModel.clearSelection()` + `requestFocus(.tree)`, routed through `onExitCommand` so it survives the markdown preview's NSTextView swallowing raw keydown. `cachedLines` + `cachedLinesKey` (`url|byteCount`) memoize the line split so arrow keypresses don't re-split a 25K-line file. When `viewModel.pendingFocusLine` becomes set (deep link from the review pane), the viewer applies it on content-load via `applyPendingFocusLineIfReady`, clamping to the loaded file's line count and clearing the slot.
- **Defaults**: project panel `minWidth: 200, idealWidth: 220, maxWidth: 420`; file viewer `minWidth: 280, idealWidth: 600` (no max). Sessions sidebar was retuned to `minWidth: 160, idealWidth: 180, maxWidth: 360` so the new columns don't squeeze the terminal at the default window size.
- **Layout switch**: `ClaudeSessionDetailView` bypasses the outer `HSplitView` entirely when neither the project panel nor a right-pane is visible, so the terminal fills the area without a stray drag handle (matches the original `.hidden` case behaviour pre-feature).

### Claude Review Pane (macOS only)
Lives in `Odin/Features/Claude/Review/`. Toggleable with `⇧⌘R`. The pane surfaces a structured branch review (per `odin-review` skill): one concern column for `correctness` / `security` / `tests` / `style` / etc., with findings streaming in live as Phase-1 reviewer workers call `mcp__odin__submit_finding`. The user clicks `Fix` (single finding) or `Fix all blockers` / `Fix all auto-fixable` (bulk) to dispatch Phase-2 fix workers via `FixActionService`. Findings carry a `file` + optional `line`; clicking the line number opens the file in the project panel's `FileViewerView` at that line via `ProjectPanelViewModel.openFile(at:line:)`. Each `ClaudeSession` carries a `rightPaneMode: RightPaneMode` (in-memory `.hidden | .diff | .review`) so the right column switches between the diff pane and the review pane.

### App-Level Glue

### Cloud Function
Source lives in `cloud-functions/claude-dev-starter/`. Node.js function deployed to GCP (`europe-north1`). In-memory rate limit: 10 cold starts per rolling hour per instance; returns HTTP 429 with `Retry-After` once the budget is spent (reads of `RUNNING` VMs are unbounded).



```bash
# Deploy (requires gcloud CLI authenticated)
gcloud functions deploy claude-dev-starter --gen2 --region=<region> \
  --project=<gcp-project-id> --runtime=nodejs22 --trigger-http \
  --allow-unauthenticated \
  --set-env-vars=API_KEY=<key>,GCP_PROJECT=<gcp-project-id>,GCP_ZONE=<zone>,GCP_INSTANCE=<vm-name> \
  --source=cloud-functions/claude-dev-starter --entry-point=claude-dev-starter
```

The VM target (`GCP_PROJECT` / `GCP_ZONE` / `GCP_INSTANCE`) is read from env vars — the function source carries no deployment identifiers, and missing values fail closed with HTTP 500 `server_misconfigured`. The function validates an `X-API-Key` header (secret stored in `API_KEY` env var, compared via `crypto.timingSafeEqual` on equal-length buffers; deploys without the env var fail closed with HTTP 500 `server_misconfigured` rather than silently disabling auth), starts the VM if stopped, and returns `{status, ip, hostKey}`. Upstream GCP errors are logged server-side but the response body returns the generic `{error: "internal_error"}` so project IDs / hostnames / policy details don't leak. The `hostKey` is the full OpenSSH public key string (e.g. `ssh-ed25519 AAAA...`) read from VM instance metadata key `ssh-host-key-ed25519`. If the VM's host key ever changes (e.g. OS reinstall), update the metadata: `gcloud compute instances add-metadata <vm-name> --zone=<zone> --project=<gcp-project-id> --metadata=ssh-host-key-ed25519=<base64-key>`

### Security
- **API key**: Stored in Keychain on device, validated by Cloud Function with a constant-time compare. Never committed to source code.
- **SSH host key**: Mandatory verification on every connect. The Cloud Function returns the expected host key; the app rejects connections if the server key doesn't match.
- **SSH private key**: Ed25519, stored in Keychain with `kSecAttrAccessibleWhenUnlockedThisDeviceOnly` (no iCloud sync).
- **OdinMCP auth**: Loopback listener + a per-launch 32-byte hex `authToken` (`X-Odin-Auth` header). Constant-time compare; missing/wrong header → 401. Token is injected into every per-session `.mcp.json` so the spawned Claude carries it automatically. Closes the "any local process can call run_background_task" gap.
- **Worker permissions**: Spawned `claude -p` workers run with a scoped `--allowed-tools` list keyed off their role (reviewer / fixer / nil). No `--dangerously-skip-permissions`. Tools outside the list fail closed.
- **Prompt-injection wrapper**: Worker stdout is sanitised through `BackgroundClaudeRunner.sanitizeForWrapper` (replaces both `<odin-background-notification>` and `</odin-background-notification>`, case-insensitive) and capped at 8 KB before being injected into the parent's next user prompt via the `UserPromptSubmit` hook.
- **Claude binary lookup**: `ClaudePath.resolve()` checks a fixed allow-list of install dirs only — no `which claude` fallback through a login shell, so a poisoned `~/.zshrc` can't redirect every session to an attacker binary. Spawn is direct (no `zsh -ilc` wrapper) with an explicit `PATH`.
- **DEVELOPMENT_TEAM**: Left empty in `project.yml` — set manually in Xcode. Do not commit team IDs to the pbxproj.

## Platform Considerations

- Single codebase targets both iOS and macOS via `platform: [iOS, macOS]` in `project.yml`
- XcodeGen produces two schemes: `Odin_iOS` and `Odin_macOS`
- `UILaunchScreen: {}` in `project.yml` is required — without it iOS runs in compatibility zoom mode
- Code signing requires manually setting Development Team in Xcode; CloudKit sync requires the iCloud capability enabled
- Terminal tab bar is hidden when connected on iOS; overlay buttons provide keyboard dismiss and tab navigation
- The Claude tab is macOS-only (`#if os(macOS)` on both the `AppTab.claude` enum case and the `Tab` in `ContentView`). New files in `Odin/Features/Claude/` are fully wrapped in `#if os(macOS)` so they compile to nothing on iOS.
- Claude terminal requires the `claude` CLI installed on the Mac (e.g. via `npm install -g @anthropic-ai/claude-code`). The app is not sandboxed, so spawning local processes works.
